# Feature coverage and gaps

Generated by `node scripts/gap-report.mjs --write` from `tests/fixtures/gap-tasks.json` (66 common application tasks) and the feature contracts in `resources/feature-contracts/`. Run `genlib coverage <task>` for one feature.

Coverage is credited per requirement, never per search hit. Each contract lists what the feature needs in a real multi-tenant app, and an implementation counts for a requirement only when a named repository test exercises it (`fixture-verified`). Lower statuses (`install-supported`, `plan-available`, `cataloged`) are shown but not counted as covered. The receiving application raises a requirement to `application-verified` with `genlib adopted <module> --test "<cmd>" --accepts <contract>#<requirement>`.

| Coverage | Tasks |
| --- | ---: |
| Full: every requirement fixture-verified | 28 |
| Partial: some requirements fixture-verified | 29 |
| Unverified: only install, plan or catalog claims | 9 |
| None: no implementation claims a requirement | 0 |

The "Search returns" column is what `quick` picks for the task phrase (lexical routing): 60 tasks route to Genlib code and 6 to external records. Routing to Genlib code does not mean the feature is covered; compare it with the Verified column.
