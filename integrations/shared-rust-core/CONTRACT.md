# Shared Rust domain core with UniFFI

The original Rust domain code, bindings configuration, fixtures and host tests are Apache-2.0. UniFFI itself is **MPL-2.0**, with file-level obligations for covered source; the host must review notices and distribution obligations for its actual dependency/build artifacts. Generated bindings and linked third-party runtime artifacts do not become Apache-2.0 merely because this pack has an Apache manifest. No upstream runtime implementation is vendored here.

`apply_change` is a deterministic immutable inventory transition. It validates IDs, titles, duplicate state and a 10,000-item ceiling, and returns typed errors. IDs use a bounded ASCII alphabet; title limits count Unicode scalar values. The same Rust implementation serves Swift, Kotlin and Python bindings. Authorization, durable storage, serialization versioning, UI state, locking and network sync remain host responsibilities.

Run `cargo test` for the shared JSON conformance fixture and failure cases. `python3 bindings/generate.py python` builds the host library and generates Python bindings with the same pinned UniFFI 0.32.2; `python3 bindings/test_python.py` exercises the actual FFI boundary. The generator also accepts `swift` and `kotlin`. Generation writes only the pack's `generated/` and Cargo `target/` directories. Cargo installation, compiler downloads and dependency resolution are deliberate developer actions, never installer hooks.

The supplied Swift/Kotlin host test files cover matching transitions and errors. Add generated Swift, the generated FFI header/modulemap, and per-architecture Rust libraries to an Apple target; add generated Kotlin plus its JNA dependency and correctly named per-ABI native library to a JVM/Android target. Run those host tests on each supported ABI. UniFFI generates binding code; it does not automatically build an XCFramework, sign an app, package Android ABIs, or promise identical behavior across third-party language binding generators. [Official binding integration](https://mozilla.github.io/uniffi-rs/latest/tutorial/foreign_language_bindings.html).

Verification is scoped per command in the manifest. Swift/Kotlin host compilation, Apple cross-compilation, Android packaging and release linking are experimental until run on the receiving project's selected toolchains. Keep Cargo.lock from verified resolution for reproducible fixture tests and review toolchain/dependency upgrades together.
